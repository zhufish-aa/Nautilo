Nautilo 是一个本地、可自由配置的多 Agent 编程工作台。统一管理 Codex、Claude Code、Kimi Code 等 CLI，定义成员与角色，让主 Agent 决策、委派、验证并协同完成任务。 Nautilo is a local, fully configurable multi-agent coding workbench. Manage Codex, Claude Code, Kimi Code and more — define members and roles, and let the main agent decide, delegate, verify and deliver.

一个工作台，管好所有 Agent

One workbench for every agent

不训练模型、不替代任何 CLI——Nautilo 是这些工具之上的编排层。 No model training, no CLI replacement — Nautilo is the orchestration layer on top of the tools you already use.

多 Provider 管理

Multi-provider management

Built-in adapters for Codex, Claude Code, Kimi Code and custom CLIs; OpenCode and Trae via plugins. Auto-detects local CLIs and versions.

Main-agent decisions

Complete directly, delegate subtasks, or emit a dependency-aware task DAG — with handoff, retry, take-over and resume.

插件机制：把任意 CLI 变成 Provider

Plugins: turn any CLI into a provider

实现一个 Adapter 接口、写一份 manifest，就能把任何 Agent CLI 接入 Nautilo 的统一会话界面——无需改动任何前端代码。

Implement one adapter interface and one manifest to plug any agent CLI into Nautilo's unified session UI — no frontend changes needed.

  • 插件市场：registry 托管在 GitHub，应用内一键安装，SHA-256 校验
  • Marketplace: registry hosted on GitHub, one-click install with SHA-256 verification
  • 发布 = 提 PR：向 registry 仓库提交 Pull Request 即可上架
  • Publishing = a PR: open a pull request to the registry repo to get listed
  • 完整 SDK 与模板：OpenCode / Trae 两个真实参考实现
  • Full SDK & template: OpenCode and Trae as real reference implementations
# 1. 复制模板 / copy the template
cp -r packages/provider-plugin-template \
      packages/provider-plugin-my-cli

# 2. 改 manifest 和适配器 / edit manifest + adapter
# 3. 构建 / build
pnpm --filter <your-package> build

# 4. 上架 = 向 registry 提 PR / publish via PR
# github.com/zhufish-aa/nautilo-provider-registry
