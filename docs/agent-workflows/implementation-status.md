# 工作流实现与验收记录

更新于 2026-11-19。此文件记录实际实现和剩余工作；设计提案中的能力不能自动算作已交付。

## 已接入的代码

- 共享领域类型、版本化 JSON 定义、JSON Schema、八个工作流 IPC 方法与运行事件。Rust 的定义序列化可以回到编辑器和 JSON Schema，未设置的可选字段不导出为 `null`。
- Rust 引擎处理命名出口、结构化结果、固定并行、动态分项、汇合、条件、有限回边和固定修订的子流程。结果提交与原生执行结束分别记录，两项齐备才推进。多轮反馈可显式引用原始节点的已完成证据。`dispatch` 控制节点将当前结果直接交给所有命名出口，不创建额外的模型轮次；结果和出口可按事件回放。
- 汇合的 `sources` 支持同一批次中重叠的依赖关系，例如 C 依赖 A、D 依赖 A+B、最后等待 C+D。独立到达记录和批次关联会随状态持久化；回路经过分派节点后建立新批次，剩余来源取消不会取消无关节点。
- 工作流、实例、提醒与追加事件在同一事务保存。启动请求有稳定 ID 和内容校验，模板修订有并发检查，调度有租约，重启后先核对既有 Run。整个子图树共用父流程的实例与并发预算。
- 执行使用既有 RunService。角色绑定保存成员、角色、Agent 和连接修订的快照；原账号、原生设置及会话由既有执行层处理。漏交会主动向原子会话发起补交轮次，最终结果或升级请求投递到原主会话；停止会继续处理在途 Run 和子图。
- 已知原生子 Agent 的状态独立对账。派发工具返回、前台轮次结束后，如果子 Agent 仍在运行，节点保留并发槽且不会推进；子任务失败、运行环境消失或超过节点期限会升级处理。原生状态和事件游标保存在节点中；取消后的清理也会保留在待处理队列，不能因前台 Run 已完成而漏掉后台工作。清理与新会话轮次串行；原会话已被后续轮次使用时保留其运行环境，并记录交回会话的结果。
- 补交使用独立的执行键，旧轮次迟到的结束记录不能覆盖新补交。重启发生在补交投递尚未确认时，保留不确定状态并升级，避免无声卡住或自动重复派发。
- 原生工作流工具提供语言和 JSON Schema、真实可用绑定 ID、模板、启动、查询与按当前实例提交。工具提供者使用弱引用，避免已销毁的调度器被工具绑定循环持有。
- 原生工具返回统一的成功/内容信封，实际 HTTP MCP 可以读到提交与重复提交回执。工具提交须回传当前实例与尝试，避免旧轮次在复用会话上推进新节点。原生后台回调保留工作流作用域。
- Codex 工作流工具通过增量的本地 MCP 接入；不为安装工作流工具提升原生动态工具版本或重建会话。桥接地址在驻留进程内稳定，每轮串行更新工具绑定，用户原有 MCP 继续合并。
- 节点可以显式选择 `completion: "structured_final"`，在最终回复中交付 `{branch,result}` 或 `{branches,result}`。它使用相同的出口、字段和去重规则；不会关闭 Harness 原有工具、MCP 或插件来实现该模式。无效回复保留为待补交资料。
- Electron 共用 renderer 已有工作流页面与侧栏入口。设计和执行共用黑白画布，支持拖动、连线改接、撤销重做、键盘移动、自动排列、草稿、模板修订、JSON 导入导出、角色选择、实例查看、子图进入与返回、消息记录和按事件回放。活动路径持续流动；回放暂停与调度暂停是独立控制。
- 节点属性可以直接配置汇合来源、阈值、剩余来源策略、列表分派、结果字段、条件匹配，以及固定修订的子流程输入和命名返回映射。结构化内容的未完成 JSON 会拦住保存与启动。重叠汇合在实时和历史投影中分别显示，回放原生子 Agent 的停止也不会改写早先的事件。
- 节点执行已接入项目工作区与验收规则。独立模式固定 Git 起点，节点各有工作区；节点修改先在候选工作区合并和验收，再推进汇总分支。子流程共用父流程的汇总分支，最终验收后等待用户决定合入原项目或保留成果。原项目在执行期间被修改时保留其内容；原生 Agent 自行提交、项目子目录和未跟踪文件也纳入检查。内部工作区目录使用固定长度名称，避免 Windows 深目录导致 Git 创建失败。
- 验收命令在执行前遵循项目命令审批；单次授权只在执行对应命令时消耗。完成的节点检查可在等待合并检查审批时保留检查点，避免重复执行。停止流程会取消可观测的验收进程；中断后缺少进程回执时保留不确定状态和工作区，停止后的旧阶段记录会退出待处理队列。
- 执行页可以查看工作区、验收命令与日志，以及保存的 Git 差异，并完成验收批准、合并或保留决定。回放不暴露实时批准操作，验收期间继续刷新状态并保留停止入口。默认展示主 Agent 冻结的任务正文，完整派发内容可展开核对。
- 旧任务计划已有转换器、可信启动入口和任务投影组件，启动后接入真实 RunService。转换器保留任务身份、成员、提示词、依赖、继续会话目标和路径/验收配置；单次派发生成两节点图，重试可引用成功依赖的已有结果。投影组件在同一事务保存原任务状态、主会话回执和追加运行事件，防止重复回执、旧尝试覆盖新尝试和旧调度器写入已被图接管的任务。**可信启动入口尚未由旧工具调用，旧工具目前仍使用原调度器。**
- 可信任务图可复用原生子会话；同一原生会话会等前一任务提交并完成验收后再执行下一项任务。重试保留原目录、未提交修改及原生身份，不重启成功兄弟任务；停止请求须得到实际退出确认后才允许重试。明确的成员并发上限会跨同一项目运行的独立任务图计算，包含尚未退出的取消中运行。
- 任务图沿用原项目的汇总目录与分支，共享同一验收锁；各任务可以使用独立目录，不另建对主 Agent 不可见的汇总分支。直接模式的项目仍保持直接模式，带路径约束的节点独立准备和验收后合入原目录。差异与检查记录继续使用原项目运行和任务编号，旧任务字段保留差异、提交和检查引用；新尝试清空当前失败证据并在历史中保留引用。
- 取消后晚到的工作区准备结果仍可保留实际目录，不能重新激活已停止任务或重复交付结果。尚未建立独立分支的规划目录不会误作可复用的任务目录。任务正文随激活事件冻结，原始派发契约仍可展开核对；界面默认显示正文，并支持长文本选择和键盘滚动。主会话返回使用用户当前明确选择的 Agent/原生身份，已经启动的子任务绑定保持冻结。
- 取消会将尚未启动的验收标记为已取消；已启动的外部检查仍由执行层核对停止结果。任务处于验收、复核或待合并阶段时，Rust 与 TypeScript 领域状态都允许明确停止。
- Node 对照端已同步 SQLite 工作流表、索引和迁移，能打开相同的持久化结构。**Node 对照端尚未实现完整工作流 IPC/执行服务。**

## 自动验证

从根目录运行 `pnpm test:workflows --browser`。

2026-11-19 当前整体验证通过：96 项 Rust 工作流测试、8 项跨语言契约检查、18 项 Chromium 交互检查；另有 1 项真实 Codex CLI 检查默认跳过。桌面与界面测试夹具的 TypeScript 检查均通过。修正独立预览的 Tailwind 源码扫描范围后，18 项浏览器检查已单独复验，弹层额外检查视口位置、层级与实际点击命中。

该命令构建所需共享包与 Node 对照 daemon，执行 Rust 工作流测试，将实际引擎快照交给 JSON Schema 和 renderer 投影检查，再在独立 Chromium 中测试生产页面。测试不使用真实账号、不启动真实模型、不替换当前桌面进程。临时 SQLite 和浏览器配置按此次运行单独创建并清理；Vite 缓存与 Electron 分离。

已覆盖的场景包括以下项目。

- 提交与执行结束乱序、重复提交、错误出口、缺字段、旧尝试、下游变量缺失时保留上游有效回执。
- 并行汇合、首个合格结果中的部分失败、回边只重跑相关节点、稳定分项键、空列表直接汇合。
- 两种完成次序下的重叠汇合、汇合中途序列化恢复、经过分派节点的多轮批次、提前获胜时跳过尚未激活的来源，以及仍有无关任务运行时识别必需来源失败。
- 原子会话漏交后主动补交、补交成功撤销提醒、截止升级、暂停与停止、重启对账、不重复派发。
- 团队派发审批、原生命令审批、取消尚未批准的流程、模板修订与布局固定、最后一层子图深度、父子暂停与共享并发预算。
- 工具方式和显式最终 JSON 方式使用同一提交契约、绑定目录不暴露 Agent 环境变量、子会话不能读取全局绑定目录。
- 前台轮次结束后等待原生子 Agent、租约到期后恢复等待、原生子 Agent 失败与期限、已完成前台 Run 的后台取消、后续用户轮次的会话归属保护、迟到前台完成记录与未确认补交恢复。
- 浏览器实际拖动与撤销、键盘编辑、命名出口改接、两路持续动画、暂停回放不暂停调度、提醒收件人、减少动态效果、紧凑窗口及无未捕获异常。
- 浏览器实际保存汇合来源/阈值/取消策略、列表项标识、固定修订的子流程与返回映射；无效条件 JSON 拦住保存，修正后保存实际值。
- 真实临时 Git 仓库中的节点隔离、Agent 自行提交、并行分支汇总、子流程共享成果、候选验收失败时不推进汇总分支、子目录越界检查、准备失败与停止后的孤立阶段清理。
- 验收命令获批前不执行、预检不消耗单次授权、等待合并检查审批时保留节点检查点、停止真实检查进程、拒绝合并保留成果，以及合并前保护用户后续修改。
- 继承全部检查与显式取消可选检查的行为不同，项目必需检查始终执行；未知验收项在启动前拒绝。
- 浏览器实际配置工作区与验收项、读取保存的 Git 差异、发送保留成果与按节点批准命令的操作；历史回放不出现实时批准按钮。浅深主题及紧凑窗口已核对截图。
- 编辑器定义和 Rust 快照符合 JSON Schema；历史投影不会提前显示未来提交；Node 迁移包含工作流表与恢复索引。
- 单任务、共享依赖与全部 64 种四任务 DAG 在两种完成顺序下正确推进；转换后的自动分发和等待依赖可以由生产页面渲染，历史状态不提前显示自动分发结果。
- 原任务和回执随图状态一起回滚，重复处理只写一份回执；新重试保留旧回执，旧完成不能覆盖新尝试；原生子 Agent 尚未停止时拒绝重复派发。原主会话替换后，已启动图的任务回执仍归原始主会话。
- 可信启动经过实际工具回调与 RunService 执行原任务，继续和重试沿用原生身份；原主 Agent 自己执行的任务不产生额外主轮次。两个任务共用同一原生会话时，漏交补交完成前不会抢占该会话。用户明确更换主 Agent 后，结果返回当前选择，已启动子任务的绑定保持不变。
- 真实 Git 检查覆盖旧项目汇总分支的接入、独立任务图的并行合入、直接模式的节点路径隔离，以及带未提交修改的失败任务重试。原差异、提交与检查引用继续投影到旧任务，历史尝试保留原引用；取消后的迟到目录证据不激活任务或重复交付。
- 任务正文与首次激活事件固定；启动后修改任务行不会改写已发计划或旧事件。公开快照和回放事件不携带私有项目快照，浏览器从原项目运行读取保存的真实差异；默认正文与完整派发内容分开显示。

这些验证包含真正的数据库和 RunService，Harness 部分使用可控适配器。**它们不等同于真实 Codex、Claude Code、OpenCode 等 Harness 的端到端验收。**

本机另已通过 Codex CLI 的真实握手、原生历史持久化、原会话恢复与工作流 MCP 工具发现检查。检查使用独立临时 `CODEX_HOME`，不读取用户登录，不发送 `turn/start` 或模型请求，不覆盖用户历史；这仍不等同于模型主动选择工具的端到端验证。复验时设置 `NAUTILO_WORKFLOW_CODEX_CLI`，运行 Cargo 中标为 ignored 的 `workflow_codex_native_cli` 测试。

## 仍需完成

1. 旧 `agenthub_delegate` / `agenthub_plan` 调度迁入同一图运行，保留旧任务回执、审批、原生会话和成功任务的重试边界。计划转换、可信启动、事务投影、原生会话与原汇总工作区已接通并单独验证；尚未切换旧工具入口。下一步需保留原生调用身份、事务创建原任务，接通审批/取消/重试回调，以及主会话最终汇总和项目收尾的持久化控制；不能用易丢失的后台等待替代恢复。默认返回数据与显式唤醒主 Agent 的语义也需按设计第 1、2 节对齐。
2. 补齐工作区中断后的人工核对与重试操作、原项目起点变化后的重新验收流程，以及外部检查进程在 daemon 硬中断后的持久化对账。当前正常隔离、候选验收、命令审批、取消和最终合并已接入；无法确认的执行会保留证据并升级，尚未提供完整恢复操作。
3. 完成 Node 对照端协议行为，或按明确的后端能力契约提供一致支持；不能把表结构兼容当作执行兼容。
4. 对每个实际 Harness 验证提交工具、显式 JSON 交付、原生会话复用、补交、审批、进程中断及恢复；补齐运行入口的完整 IPC 验收。
5. 补齐实时定位到端口的校验、子图的动态扩展权限和预算、明确的技术重试与结果待确认恢复操作。已提供节点属性配置；更复杂的结果类型和输入映射可以通过节点内 JSON 或完整流程定义编辑，原始结果和故障记录已保留。
6. 补齐按需桌面通知、移动端待办与会话内流程入口。当前引擎消息会写入原会话并触发原会话的新轮次，系统通知与移动界面还未作为本功能验收。
7. 静态校验还需覆盖每条可达路径的数据可用性与默认值。当前已检查已声明输入、节点/出口引用和模板结构，激活时仍会验证实际数据；不能把激活时保护称作完整静态证明。

当前代码仍在实现和验证中。测试没有关闭 Nautilo，也没有把开发中的 Rust daemon 替换到用户正在使用的桌面实例。完成上述剩余项并按设计验收后，再交付完整功能。
