## 11.1 子代理（Sub-agent）：能生小 Agent 去干活

Agent 遇到一个任务，可以**派一个"小 Agent"去处理**（子代理），就像你手下带实习生。

- **为什么需要？** 有时一个任务很独立（比如"研究某个文档并汇报"），如果主 Agent 自己一步一步做，会占住上下文、拖慢主线。派子代理去做，主 Agent 可以继续干别的；子代理把结果带回，主线只收到**一段精炼的汇报**。
- **隔离性**：子代理有自己的会话/上下文/工作目录，它干的事不影响主 Agent 的账本（除了最后的汇报会回来）。
- **权限边界**：DSH 对子代理能做什么有约束（子代理不能随意"越权"创建更深的东西），这是账号安全的重要一环。

DSH 提供了一堆 `subagent-*` 包（比如 subagent-codex 那种跟某个具体 Agent 品种对接的）。它的价值在于：**"多 Agent 并行"被做成了标准能力，而不是临时 hack。**

## 11.2 持久化：日志搬家到磁盘

第 3 章说"账本"要能恢复——那账本存哪？DSH 用**插件**来管持久化（又是"一切皆插件"）：

- `session-persistence-jsonl`：把事件按 JSON Lines 格式一条一行存成文件。
- `session-persistence-sqlite`：存进 SQLite 数据库。

**为什么不用"一个内置数据库"？**还是能力缝的思想：存储是你的地盘你做主。想存文件用 jsonl，想查得快用 sqlite，想换存储实现换插件。

关键点：**日志怎么进磁盘，和日志长什么样（真相）是分开的**。DSH 里很多操作会" flush（冲刷）"，即把内存里攒的事件落盘，确保崩溃时账本完整。

---

## 11.3 权限与交互（Interaction）

有些工具不能随便调。DSH 有 `interaction`（交互）包，管"用户批准"和"权限预设"：

- **用户批准（user-approval）**：当模型要执行**有副作用的动作**（跑命令、写文件、发消息给别人）时，可以停下来问用户"你同意吗？"用户批准才执行。这既安全，也是"人在回路（human-in-the-loop）"。
- **权限预设（permission-presets）**：可以给不同场景配好"哪些能自动做、哪些要问"的规则。

**结合第 6 章**：工具系统管"能不能跑得对"（并行、顺序、入账），权限系统管"能不能跑"（批准、禁止）。两者分得很开，各司其职。

---

## 11.4 装配：把所有零件拼成一台能跑的机器（Bundle）

你可能觉得："这么多包，我总不能一个个装吧？"DSH 提供了 **bundle（装配包）**：

- `bundle/base`：基础骨架，装了最核心的零件。
- `bundle/web-app`：拼出一个带 Web 界面的完整应用。
- `bundle/headless`：不带头，纯后台跑。

**Bundle 就是一个"预装好的配置清单"**——把某场景需要的所有插件一次性装配起来，像买一台"组装机"而不是自己攒散件。这也是为什么 DSH 可以"一个仓库几十个包，但用户只跟一两个 bundle 打交道"。

还记得第 2 章吗？这一切最终还是"插件 + Cordis 装配"。Bundle 只是"别人帮你装好了"。

## 11.5 测试：DSH 怎么保证不出幺蛾子

一个这么复杂的系统，测试超重要。给你看三种典型测试：

1. **不变式测试（invariant）**：保证"账本永远一致"这类黄金规则。比如"Surface 上的一切都能在日志里溯源"。
2. **端到端测试（e2e）**：像第 8.5 章那个 `request-cache.e2e.ts`——连真 API 发一串请求，断言"每次缓存都命中"。这种测试是 DSH 缓存哲学的"考试卷"。
3. **回归测试**：修完 bug 后，保证不会再犯。

**给新手的话**：你学 DSH 不必先读测试，但当你怀疑"这个行为会不会乱来"时，去测试里找答案——**测试就是"这个系统承诺了什么"最诚实的说明书。**

## 11.6 新手阅读路线图：从哪下手？

如果你要真正上手读 DSH 源码，给你一条"七步路线"，一步一个脚印：

| 步骤 | 读什么 | 收获 |
|---|---|---|
| 1 | `packages/llm/llm/src/types.ts` | 摸清"统一消息/内容块"长什么样（很小但全书基石） |
| 2 | `packages/core/session/src/surface.ts` | 搞懂 Surface 与 append/replace（缓存的分水岭） |
| 3 | `packages/core/session/README.md` | 从文档角度再印证"日志是唯一真相" |
| 4 | `packages/core/agent-loop/src/agent.ts` | 看 ReactLoopAgent 怎么转循环（turn/step/状态机） |
| 5 | `packages/core/agent-loop/tests/request-cache.e2e.ts` | 看"缓存必须命中"的验收测试 |
| 6 | `packages/compaction/compaction-basic/src/region.ts` + `summarizer.ts` | 啃最硬的压缩（选段 + 摘要前缀复用） |
| 7 | `packages/bundle/base` | 看怎么把它拼成整机 |

**心态提示**：不要从头到尾线性读几十个包。**按"主线（循环→缓存→压缩）"读，其他（工具、子代理、权限……）需要时再深挖。** 这是最高效的路径。

## 11.7 一句话记忆法：32 字总结 DSH

> **一切插件，账本不改；表面投影，缓存为王。**
> **循环驱动，工具成对；先削后压，绝不瞎动。**

逐字拆解：

- **一切插件**：第 2 章，所有能力都能插拔。
- **账本不改**：第 3 章，事件日志只增不改、可重放。
- **表面投影**：第 4 章，模型看到的是从日志算出的 Surface。
- **缓存为王**：第 8 章，前缀稳定 = 命中 = 快 + 便宜。
- **循环驱动**：第 5 章，turn/step 状态机让机器转起来。
- **工具成对**：第 6 章，tool-call/tool-result 永远配对。
- **先削后压**：第 10 章，先无模型裁剪，不行再模型压缩。
- **绝不瞎动**：第 10 章，稳定性检查不过绝不提交、并发绝不打架。

## 11.8 全书总复习（把 11 章串成一句话故事）

> DSH 用一根只增不改的账本(3)记录一切；从账本投影出给模型看的 Surface(4)；用带状态机的 Agent Loop(5)驱动模型和工具你追我赶(6)；通过让 system 前缀稳定、只增不改，把缓存命中率拉满(8)；LLM 靠接口抽象接遍厂商(7)；当对话太长就用一套"事务化"压缩(9)把它折起来，而压缩连自己的请求都精打细算复现缓存前缀(10)；最后用插件、子代理、权限、存储和 bundle 拼成一台完整可用的机器(2,11)。
