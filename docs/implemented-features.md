# Nautilo 已实现功能总览

整理日期：2026 年 11 月 16 日。本文按当前工作区源码整理，包含尚未提交的修改；桌面端源码版本为 **0.2.16**，Android 源码版本为 **0.1.23**。本轮变化和验证边界见 [质量迭代实施与交接](quality-iteration-2026-11-16.md)。

Nautilo 是运行在用户电脑上的多 Agent 编程工作台。它管理本机的 Coding Agent CLI、连接和工具资源，提供统一会话、团队调度、文件审阅、Git、浏览器操作，以及通过 Android 继续控制电脑的能力。

本文记录**已经存在的功能及其实现范围**，不作为下一迭代待办。区分以下三种状态：

- **产品功能**：已有界面入口及对应执行链路。
- **后台能力**：已有服务、存储和 IPC，尚未形成完整的界面流程。
- **适配能力**：由具体 Harness 的原生协议、版本和能力声明决定，不表示所有 Harness 无差别支持。

源码中存在实现，不等于所有安装包都已包含该实现，也不等于每个账号、网络和 Harness 版本均经过真实环境验收。本文不把过往报错截图直接当作当前缺失，也不把接口定义当成完整产品功能。

## 2. 桌面运行架构

当前桌面主线是 **Electron + React + 独立 Rust daemon**。

| 层 | 已实现职责 | 源码 |
| --- | --- | --- |
| Electron 主进程 | 桌面窗口、系统交互、原生浏览器、WebContents / CDP、后端连接 | [src/main](../apps/desktop/src/main/) |
| Preload | 向渲染层提供受限的白名单接口 | [src/preload](../apps/desktop/src/preload/) |
| React 前端 | 页面、会话工作区、时间线、设置、面板与 Zustand 状态 | [src/renderer/src](../apps/desktop/src/renderer/src/) |
| Rust 核心后端 | 项目和会话服务、运行调度、账号与协议、事件、SQLite、远程连接 | [nautilo-core](../rust/nautilo-core/src/) |
| Provider 插件 | 各 Harness 的原生协议、参数、事件、恢复与生命周期适配 | [rust/plugins](../rust/plugins/) |
| 共享协议 | 领域模型、IPC schema、运行时事件和插件契约 | [packages](../packages/) |

前端通过壳层和认证 IPC 请求后端，不直接操作数据库、shell 或 Git。运行时事件追加保存，界面从事件投影重建状态；会话身份、单轮运行、团队任务分别管理。

仓库保留 Node daemon 对照实现和 Tauri 入口；它们不改变当前 Electron + Rust 的启动路线。

## 3. 项目、会话与消息

### 3.1 项目与会话管理

| 功能 | 当前实现 |
| --- | --- |
| 本地项目管理 | 添加、创建、修改、移除项目，记录工作目录；项目与会话关联 |
| 新建会话 | 在选定项目内选择 Harness、连接及模型后发送第一条消息 |
| 会话配置 | 保存连接及版本、模型、推理强度、权限、原生运行模式和协作团队 |
| 会话标题 | 初始标题与生成标题；侧栏展示标题并支持会话管理 |
| 会话历史 | 持久化用户消息、回复、工具活动、交互和运行状态，支持分页及增量读取 |
| 会话组织 | 项目分组、父子关系、运行和未读标记、分批展开；单纯打开会话不作为新消息更新 |
| 会话搜索 | 搜索会话标题和项目名称，提供键盘操作入口；不是聊天正文全文检索 |
| 持续挂载 | 会话工作区在页面切换时保留，避免每次导航都重新创建整套聊天界面 |

### 3.2 发送、流式与顺序

- 用户发送后先显示自己的消息，再持续接收正文、思考和工具事件。
- 同一条活动按稳定身份更新；流式增量、最终回执和历史同步不应各自追加一份副本。
- 运行中可以发送**引导**，也可以将消息**排队**，查看队列、取消排队或将队列项转为引导。桌面输入支持 Enter 引导、Ctrl+Enter 排队、Shift+Enter 换行。
- 引导消息形成新的显示边界：此前内容留在原位，此后的活动和回复显示在引导下方，原生运行身份保持连续。
- 中间说明、工具和思考可以折叠，最终回复保留在折叠区外。已有委派卡片承载的内部派发记录不再重复作为普通聊天内容展示。
- 自动跟随最新内容；用户主动向上查看历史时停止强制跟随，提供返回底部入口。
- 停止、失败和中断保留已收到的内容，并记录实际状态，不用“已完成”代替取消或异常。

### 3.3 内容展示与交互

| 功能 | 当前实现 |
| --- | --- |
| Markdown | 标题、列表、引用、链接、表格、行内代码、代码块和代码高亮 |
| 思考 | 展开全文；折叠时显示摘要，流式更新末尾内容；只展示上游实际返回的内容 |
| 工具活动 | 命令、读写文件、MCP、Skills、浏览器等采用不同图标与摘要，详情按需展开 |
| 代码执行 | 输入代码、输出、子工具调用与后台任务状态分别呈现 |
| 图片与文件 | 消息附件、图片预览、文件引用和工作区内预览入口 |
| 原生审批 | 展示请求、允许或拒绝、授权范围，并把用户选择交还原生运行 |
| 原生提问 | 单选、多选及受支持的表单输入；回答后在原位置保留记录 |
| 扩展交互 | 通过适配契约传递选择、输入、编辑及通知等请求，不统一自动取消 |
| 原生命令 | 发现和执行 Harness 声明的 slash command，支持需要后续选择的命令流程 |
| 错误 | 错误代码、原因、详情、可重试性与相应设置入口 |

桌面输入草稿已通过独立 Repository 加密持久化，保存文本、附件引用、版本和提交消息身份。关闭窗口先等待保存；重启恢复不自动发送，附件重新核对可读性，保存冲突保留本窗口内容。发送回执按消息 ID 和草稿版本对账，旧回执不能清空后来输入的内容。异常退出只能恢复最近一次成功保存的版本。它与 Android 加密待发送箱、源码编辑器草稿仍是独立机制。

实现入口：[会话功能](../apps/desktop/src/renderer/src/features/sessions/)、[时间线](../apps/desktop/src/renderer/src/features/timeline/)、[sessions store](../apps/desktop/src/renderer/src/stores/sessions.ts)、[消息时间线](../apps/desktop/src/renderer/src/lib/conversation-timeline.ts)。

## 4. 已接入的 Harness

### 4.1 接入清单

| Harness | 接入位置 | 已有适配范围与主要边界 |
| --- | --- | --- |
| Codex | 内建 Rust adapter | app-server 等原生入口、流式、原生会话、交互、工具、模型和用量；保留所选账号的原生 Apps / 插件能力 |
| Claude Code | 内建 Rust adapter | 原生结构化会话、流式事件、思考、工具、交互、图片及原生配置合并 |
| Kimi Code | 内建 Rust adapter | ACP / 原生入口、会话、配置选项、工具和交互；图片传递随入口能力不同 |
| Custom CLI | 内建通用 adapter | 可执行文件及参数模板、请求 JSON / 环境变量、进程输出和取消；私有协议由用户程序消费 |
| OpenCode | Rust 插件 | server 会话、流式 part / delta、工具、原生历史、终端交接、会话级宿主 MCP 工具 |
| Pi | Rust 插件 | 原生 RPC / JSONL、会话恢复、思考与工具进度、用量、扩展交互、历史及终端；子 Agent 覆盖已适配的扩展结构 |
| Oh My Pi | Rust 插件 | 原生会话、扩展交互、子 Agent 订阅、工具进度、用量、历史及终端；保留原生持久化与扩展 |
| Command Code | Rust 插件 | 会话与原生资源、流式事件、工具、用量、历史读取及终端交接 |
| DeepSeek Harness | Rust 插件与桥接资源 | 常驻会话、动态模式、模型配置、思考 / 文本流、PTC、子工具、用量和上下文；不包含原生 Web 界面交接 |
| Trae | Rust 插件 | 原生 ACP 与开源 trae-agent 接入路径，连续对话、工具、图片 / 推理参数及取消；未声明原生终端历史能力 |
| Antigravity | Rust 插件 | 官方 `agy acp`、Google 登录、同会话进程复用、配置、流式和交互；模型与认证遵循官方接口 |

各 Harness 都有可执行文件、参数和环境配置的管理入口。插件声明的能力参与界面和运行选择，不能由“插件已加载”推断所有原生功能均完整适配。

### 4.2 共同实现的接入机制

- 区分原生会话与单轮请求；支持常驻协议的接入复用运行环境，轮次结束不直接等同于进程退出。
- 保留原生会话 ID、父调用关系、工具 call ID 及可获得的消息身份。
- 将正文、思考、工具更新、用量、交互、子会话和异常转换为统一事件。
- 取消传递到实际运行或子进程，保留收尾输出；原生取消与程序崩溃分别处理。
- 启动参数来自传输适配、已声明能力或用户配置，不以统一关闭 Apps、MCP、Skills、扩展来换取启动成功。
- 原生历史同步使用稳定身份和终端生命周期；终端占用期间的回读不启动新的模型轮次。
- 模型、effort、service tier、上下文、图片及输出 schema 按对应原生接口传递，不给不支持的 CLI 编造参数。

### 4.3 DeepSeek Harness 的专门能力

模式列表从实际 Harness 发现并缓存，支持用户手动刷新，不固定写死为标准 / PTC / 极简 / 创造四项。

PTC 的 `run_code` 不仅展示为“运行了一段代码”：接入实际子调用和调用关系，显示命令、文件、MCP 等子工具的执行、输出和后台任务状态。推理与文本持续更新，用量和上下文单独归档。

### 4.4 账号与原生资源的边界

同为 Codex，两个登录账号的 Apps、远端插件和授权工具也可能不同。Nautilo 保留当前账号，不能把另一账号已有的 Google Drive / GitHub 授权自动视为本账号已授权。

Antigravity 目前按官方 Google 认证和 ACP 模型工作，不等于已经支持任意第三方 API；官方登录身份也不能简单当作可由任意目录隔离的多个 Google 账号。

实现入口：[内建 adapters](../rust/nautilo-core/src/adapters/)、[Rust 插件](../rust/plugins/)、[插件 SDK](../rust/plugin-sdk/)。说明见 [Provider 插件契约](provider-plugins.md)、[Antigravity](antigravity-plugin.md)。

## 5. API、账号、模型与协议

### 5.1 连接与模型管理

| 功能 | 当前实现 |
| --- | --- |
| API 协议 | OpenAI Responses、Chat Completions、Anthropic Messages |
| 连接编辑 | 名称、协议、Base URL、密钥、启停和删除 |
| 版本化连接 | 保存生成新版本；会话和请求可绑定实际版本，避免新设置悄悄改变旧请求身份 |
| 密钥保存 | 后端凭据服务保存；普通界面和导入预览不返回明文密钥 |
| 原生登录 | Codex、Claude Code 登录配置；Antigravity 由官方 CLI 完成 Google 登录 |
| 模型配置 | 获取模型、手工添加、显示名称、上游 ID、启停、排序及默认值 |
| 推理配置 | 是否发送推理强度、可选档位、自定义档位和默认档位 |
| 模型能力 | 上下文窗口、图片输入开关、价格和缓存价格 |
| 模型选择 | 搜索、连接选择、可用模型及推理档位；以已配置或原生实际发现的模型为依据 |
| 连接诊断 | 配置、凭据、目录或传输握手等阶段的实际结果与耗时 |
| 登录异常 | 对可识别的认证失效、权限、额度、协议、网络和会话分歧给出对应原因 |

### 5.2 从原生 Harness 导入 API

入口：**设置 → 供应商与账号 → API 连接 → 从 Harness 导入**。

已覆盖 Codex、Claude Code、Kimi Code、OpenCode、Pi、Oh My Pi、Command Code、Trae Agent 和 DeepSeek Harness 的相应原生配置格式。

扫描读取端点、API 凭据引用和声明的模型；支持环境变量引用及部分文件引用。候选项显示来源，可选择后导入，相同协议、规范化地址和凭据合并来源及模型。导入不会批量启用 Harness 内置的整个模型目录。

扫描和导入为本地操作，不额外请求模型目录；不执行配置中的密钥生成命令，不把 OAuth / 浏览器登录令牌变成 API Key。导入后的密钥进入已有凭据存储。

### 5.3 跨 Harness 账号网关

已实现选择 Codex / Claude Code 登录连接后，通过本机账号网关向其他适配 Harness 提供模型调用。网关保持账号、连接版本及原生会话身份，外层 Harness 继续执行自己的工具循环。

这不等于把账号凭据或该账号的所有 Apps 工具复制给外层 Harness。是否可用仍取决于账号状态、目标 Harness 和协议适配。

协议桥按实际需要转换请求、流式文本、思考与工具信息；Responses 原生链路与 Chat Completions 转换链路分别处理。

实现入口：[connection_service](../rust/nautilo-core/src/application/connection_service.rs)、[原生 API 导入](native-api-import.md)、[account_gateway](../rust/nautilo-core/src/runtime/account_gateway.rs)、[模型编辑器](../apps/desktop/src/renderer/src/features/agents/ModelConfigurationEditor.tsx)。

### 6.2 MCP 连接复用

Rust 后端已有 daemon 持有的 MCP 进程池，对受管理的 stdio 服务预热并提供本地中转。符合复用条件的调用可复用已启动的服务，减少每轮重新拉进程、初始化 MCP 的开销。

复用区分配置、工作目录和客户端握手等条件。它不是把不同账号、环境和目录下的任意 MCP 混成一个全局连接，也不代表所有原生自带 MCP 都由 Nautilo 接管。

实现入口：[CapabilityService](../rust/nautilo-core/src/application/capability_service.rs)、[ResourceService](../rust/nautilo-core/src/application/resource_service.rs)、[资源同步界面](../apps/desktop/src/renderer/src/features/agents/ResourceSyncDialog.tsx)、[MCP 进程池](../rust/nautilo-core/src/runtime/mcp_pool/)。原生合并方式见 [原生 CLI 资源](native-cli-resources.md)。

## 7. 工作区助手、团队与任务

### 7.1 工作区助手

- 独立选择调度模型、连接、推理强度及每条指令的调度步数上限。
- 流式回应，保存助手对话、设置及记忆记录。
- 查询电脑上的已有会话、状态和所需历史片段。
- 将工作派发到指定会话并展示派发卡片，可以打开目标会话核对真实执行。
- 会话动态区区分需要处理、运行中和最近更新，支持筛选与跳转。

### 7.2 团队配置与 DAG

| 功能 | 当前实现 |
| --- | --- |
| 团队管理 | 创建、编辑、删除团队，维护成员与启用状态 |
| 成员配置 | 角色、Harness、连接、模型及相应运行设置 |
| 委派策略 | 仅主 Agent、需要确认、自主委派等策略参与实际调度 |
| 计划与委派 | 向主 Agent 暴露宿主编排工具，调用已配置成员并建立真实任务与子会话 |
| 任务依赖 | DAG 依赖、可执行状态、串行任务、并行分支和汇合 |
| 状态与结果 | 任务、成员、运行状态及结果记录，区分等待、执行、完成、失败和取消 |

### 10.2 网络方式

| 模式 | 当前行为 |
| --- | --- |
| 自动 | 优先尝试直连，必要时使用加密中继 |
| 直连 | 业务数据要求实际 IP / UDP 直连，不静默切为中继业务流量 |
| 中继 | 使用公共或自定义兼容 Iroh 节点，跳过业务直连尝试 |
| 局域网 | 在本地网络中连接，不依赖互联网中继和发现 |

电脑端已有公共节点选择、延迟刷新和自定义中继地址。支持自部署兼容 Iroh 中继，部署要求另见文档；它不是任意 HTTP 代理服务器。

直连依赖实际网络、NAT、UDP 和系统路由。Android VPN 禁止旁路或强制接管 UDP 时，应用不能绕过系统权限强制绑定物理网络；允许该应用绕过 VPN 后可使用直连。手机和电脑需要使用兼容的远程协议版本。

### 10.3 后台与恢复

- Android 前台连接服务独立于聊天页面维持连接和只读探测。
- 切后台暂停页面读取，不主动取消电脑任务；回前台恢复同步并沿用事件游标。
- 网络变化时重新检查路径，连续探测失败后再回收通道，避免短暂波动就重置整条连接。
- 暂时同步失败与发送回执未知分开显示；短暂恢复不反复闪出错误提示。
- 待发送指令保留原始 ID，恢复后按电脑回执对账，不盲目生成另一条相同请求。

无法保证手机被系统强行停止、电脑休眠 / 断网或任意 NAT / VPN 条件下仍不断线。

实现入口：[Rust remote](../rust/nautilo-core/src/runtime/remote/)、[电脑远程设置](../apps/desktop/src/renderer/src/features/settings/remote/)、[手机传输](../apps/mobile/app/src/main/java/app/nautilo/mobile/transport/)。说明见 [远程连接](remote-access.md)、[直连发现](remote-direct-discovery.md)、[中继部署](remote-relay-hosting.md)。

| 远程设备 | 加密身份、配对确认、撤销，手机本地身份与待发送记录加密保存 |

Nautilo 的策略和审批不是操作系统级隔离保证；原生权限能力、用户选定模式及系统限制仍共同生效。

实现入口：[Rust security](../rust/nautilo-core/src/runtime/security/)、[权限策略界面](../apps/desktop/src/renderer/src/features/settings/PermissionPolicyCard.tsx)、[事件协议](../packages/event-protocol/src/index.ts)、[IPC schema](../packages/schemas/src/ipc.ts)。

## 14. 界面与性能机制

已有浅色 / 深色、跟随系统、主题注册与自定义主题配置；中英文界面、统一字体和按类型显示的图标。通用按钮、弹层、选择器、提示、空状态和错误组件可以跨业务复用。

桌面已有页面 / 面板过渡、弹层和发送消息的动效，并尊重减少动态效果设置。Android 使用原生 Compose 转场、按压反馈、输入区展开及面板动效。本文只记录机制存在，不将此等同于视觉效果已经达到最终设计验收。

性能方面，已有长会话虚拟列表、可见区域代码渲染、延迟加载页面与 Monaco 语言 Worker、读取合并与缓存、异步响应作用域校验、动态 Harness 模式缓存，以及手机事件批量补读。

这些优化针对不同层次：MCP 预热减少工具初始化，常驻适配减少 Harness 重启，虚拟化减少界面渲染量；它们不能消除供应商推理、网络或原生启动自身的全部耗时。

## 15. 已落地的后台配置能力

本节与上面的产品入口分开记录，避免把后台接口说成用户已能在设置中完整操作。

| 能力 | 已有实现 | 当前产品化范围 |
| --- | --- | --- |
| 配置方案 | 捕获资源 / Harness / 连接，导入、导出、列表、删除、预览及应用；去除敏感字段，应用前核对快照 | 已有 Rust / Node 服务与 `configuration.*` IPC，尚无完整桌面配置方案页面 |
| 工具服务绑定 | `image`、`vision`、`search` 的连接、版本、模型和启用状态校验及保存 | 已有 schema / 存储 / `integration.get/save`；未见这些绑定驱动统一工具执行的完整消费链，不能记为独立工具服务已全面可用 |
| 可选账号路由 | Codex / Claude 登录连接的网关设置和运行时路由消费 | 已有实际账号网关链路，范围见第 5 节；不覆盖任意其他账号体系 |

配置方案导出不携带可移植的账号登录身份；新机器缺少凭据或原生账号时需要重新配置，不是假设导入文件就能复用授权。

实现入口：[integration_service](../rust/nautilo-core/src/application/integration_service.rs)、[可移植数据边界](../rust/nautilo-core/src/application/integration_service/portable.rs)、[integrations schema](../packages/schemas/src/integrations.ts)。
