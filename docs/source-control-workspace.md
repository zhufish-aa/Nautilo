# 源码管理工作区

当前运行路线仍为 Electron + React + Rust。源码管理是通用工作区能力，不放入任何 Harness 适配器，也不改变各插件的原生能力归属。

## 入口与作用域

项目详情和会话工具栏提供“源码管理”。会话入口从数据库读取已绑定的 `nativeWorkingDirectory`，没有绑定时使用项目目录；传入的项目必须与会话匹配。后台再用 Git 确认实际工作树根目录，因此独立 worktree 不会误操作主目录。

`health.get.features.sourceControl = 1` 声明基本接口，`sourceControlHistory = 1` 声明提交详情和历史差异，`sourceControlHistoryPaging = 1` 声明可搜索的分页历史，`sourceControlEditing = 1` 声明文本编辑与文件冲突处理。界面按实际后台能力提供入口，旧后台没有新接口时不发送新请求。更新源代码本身不代表正在运行的旧 exe 已升级。

## 当前流程

- 查看实际 Git 状态、暂存差异与工作区差异；显示原生重命名、未跟踪文件、冲突和子模块标记。
- 显式初始化仓库，不自动创建首次提交，不覆盖原有文件，也不在已有仓库的子目录重复初始化。
- 更改以一份文件列表呈现，突出文件名并另行显示目录；勾选框对应真实暂存区，半选表示仅部分内容已选。支持单选、全选和取消选择，提交仅包含已选内容，保留未选编辑；提交说明在文件列表底部，支持多行和按工作树保存草稿。
- 默认使用 Monaco 展示完整文件的语法高亮、行号和差异；窄面板自动使用统一视图，用户可切换并排并记住偏好。已选内容和后续工作目录编辑分别读取原生版本，历史视图只读。
- 逐块和逐行选择收在“按行选择”入口中。后台从新的原生差异重建选中补丁，校验仓库状态、补丁身份和行号，不接受界面提交任意补丁。暂存与取消暂存均保留其他文件和工作目录原文，覆盖相邻替换、EOF 和 CRLF 的边界情况。
- 创建和切换本地分支；未处理的更改阻止切换。分支已被另一个 worktree 占用时，在选择器中标明。
- 按每页 50 条查看当前分支可达的提交，可按提交说明（含正文）或至少 4 位的提交哈希搜索。翻页沿用打开时的提交，分支出现新提交时可手动刷新。旧后台仍显示最近 20 条。选择提交后显示说明、作者、时间、父提交及变更文件，再选择文件查看该提交中的实际版本差异。支持首次提交、重命名、删除与二进制文件，合并提交明确与首个父提交比较，不拿当前工作目录冒充历史内容。
- 远程和分支次级操作放在更多菜单中；远程获取、拉取和推送均由用户显式操作。拉取只允许快进，推送指定当前分支，不强制覆盖历史。
- 拉取来源与推送目标分别选择，读取原生 upstream/push 配置；推送到个人 fork 时保留已有拉取上游，仅在分支尚无上游时发布并建立跟踪。
- 冲突解决后暂存并提交完成合并。选择保留当前内容导致暂存树与 HEAD 相同时，仍允许创建实际的双亲合并提交。
- 冲突编辑器分别读取原生 stage 1/2/3、暂存区与工作目录；对照标为 Git ours/theirs，避免在变基中误称分支归属。可以手动编辑、采用完整版本或选择删除，保存文件和标记已解决是两个操作；普通文本也可编辑后仅保存或加入此次提交。
- 版本令牌绑定实际根目录、文件路径、HEAD/分支、该文件的索引记录、有效配置/属性、原生操作状态与工作目录内容。外部修改后保留草稿，先刷新并核对对照版本；后台拒绝旧版本覆盖。保存使用同目录临时文件与替换，完整版本先在 Git 管理目录准备，正常退出清理临时文件，避免把临时内容暴露为未跟踪文件。
- 手动编辑保留原文件的 UTF-8 BOM 与 CRLF；文本预览和写入均以 4 MiB 为界。二进制、其他编码和更大文件采用原生 Git 完整版本，不以截断文本写回。选择完整版本时仅使用已核实的原生索引对象和模式，保留符号链接、可执行位与原生过滤后的工作目录版本。
- 若文件已保存但暂存或刷新失败，返回明确的部分成功结果，界面保留草稿和重试入口，避免把已写入说成未保存。草稿按工作目录和路径保留，支持返回后恢复、采用版本的撤销/重做；外部提交或删除使文件从更改列表消失时仍可找回，文件暂不可用时保留可复制的文本。
- 放弃一个已跟踪文件的未暂存编辑前，核对用户查看过的文件内容与仓库状态。已观察到的新编辑会使请求失败；不把它描述为对任意外部写入者的文件事务隔离。

Git 通过无 shell 的参数和 NUL 分隔路径列表调用，保留用户的 Git 配置、身份、签名和钩子。后台按工作树串行处理请求，状态令牌绑定根目录、索引、原生状态、合并目标和配置，避免旧界面对新暂存内容或新远程配置执行操作。原生 Git 的锁仍负责 Git 自身的一致性。

Git 子命令设有等待上限，输出与预览长度有边界；二进制、过大文件和编码状态显式显示。完整代码视图与按行补丁均按可见区域渲染，切换来源不复用另一来源的旧内容；提交切换的迟到响应也不能替换当前选择。后台管道缓冲位于堆上，避免较长的异步调用链耗尽 Windows 工作线程栈。

Monaco 的语言后台由 `lib/monaco-workers.ts` 分配：TypeScript/JavaScript、JSON、CSS 系列和 HTML 系列使用各自 Worker，其余基础编辑请求使用 Editor Worker。构造器按语言延迟加载，保留内联载荷以适配打包窗口。不能把所有标签都分配到通用后台，否则 TypeScript 的 `getNavigationTree` 等请求会报缺少方法；开发时更换配置后需刷新渲染页，替换已创建的旧后台。

Electron 与共享前端生产构建使用 `worker-build.vite.ts` 依次编译独立 Worker，限制多个语言后台同时保留语法树造成的峰值内存；运行时的并行能力不变。本机默认 Node 堆限制下生产构建已通过，语言构造器保留为独立的延迟加载块。

文件替换前后核对已观察到的文件、索引和配置变化；这不是对任意外部写入者的事务隔离。草稿存储不可用时明确显示仅在当前运行中保留，关闭窗口前尝试保留并阻止无提示丢弃。文本冲突标记显示提示，最终暂存仍由用户显式操作，不把标记识别器当成语法证明。

两张 ImageGen 设计稿分别约束更改页与提交记录页。实现保留项目字体和全局外观，Git 面板使用紫色选中态、文件类型图标、小型提交区和同一套细边框；左侧项目栏、Git 面板及内部文件列表均可拖动调宽并记住尺寸，分隔线也支持键盘操作，Git 可最大化。设计稿和生成提示词存放于 D 盘的 `work/design/`，用于布局参考，不把图片当成可交互界面。

## 代码位置

- Rust：`runtime/source_control.rs`、`source_control_patch.rs`、`source_control_content.rs`、`source_control_history.rs`、`source_control_file.rs` 和 `runtime/git/source_control_io.rs`；应用层解析作用域，IPC 注册在 `application/ipc_handlers.rs`。
- Node 对照实现：`runtime/source-control*.ts` 与 `application/source-control.ts`。
- 协议：`packages/schemas/src/ipc.ts` 的 `scm.status`、`scm.diff`、`scm.mutate`、`scm.commit`、`scm.commitDiff`、`scm.history`、`scm.file` 和 `scm.save`。
- 界面：`SourceControlDrawer.tsx`、`SourceControlPreview.tsx`、`SourceControlHistory.tsx`、`SourceControlDiffView.tsx`、`SourceControlEditor.tsx`、`source-control-editor-drafts.ts` 和 `source-control.css`，复用 `DiffCodeEditor` 与可记忆尺寸的 `ResizeHandle`。
- 检查：Rust `source_control_tests.rs`，Node 和桌面各自的 `source-control.test.mjs`。

状态和引用解析依据 Git 的 [porcelain v2 文档](https://git-scm.com/docs/git-status#_porcelain_format_version_2) 与 [引用元数据文档](https://git-scm.com/docs/git-for-each-ref)；暂存区恢复使用 [git restore](https://git-scm.com/docs/git-restore)，路径列表遵循 [NUL 分隔路径约定](https://git-scm.com/docs/git-rm)。

## 验证边界与后续工作

本阶段 14 项 Rust、17 项 Node 和 24 项桌面 DOM/编辑器检查通过，统计与最后交互修改后另跑对应的定向检查。Git 检查使用 D 盘临时仓库与本地 bare 远程，未对开发仓库执行暂存、提交或远程推送。DOM 检查没有跳过，未自动打开应用做视觉验收；图像生成只用于用户要求的设计稿。

冲突与文本编辑另外新增 6 项 Rust、9 项 Node 检查，覆盖完整版本、手动保存、旧版本拒绝、属性变化、Native 准备期间的外部编辑、暂存失败后的部分成功、BOM/CRLF、符号链接模式、删除一方、工作树隔离、外部目录链接和较大文本。9 项编辑/草稿 DOM 流程、1 项实际编辑器回调契约及 1 项变基状态提示检查补入后，受影响桌面检查共 35 项；保留原终端、历史和部分暂存的回归范围。

另以独立数据目录运行实际 Rust exe，经认证 IPC 完成能力读取、注册项目、完整版本和差异读取、暂存、提交、提交详情、历史差异及独立 worktree 检查。共享包构建、桌面两侧类型检查和前端生产构建通过。

语言后台修复另有 4 项编辑器/分配契约和 3 项真实 Worker 协议检查：通用后台能复现已报告的 `getNavigationTree` 错误，专用后台执行 TypeScript/JavaScript 的结构与语法请求，以及 JSON/CSS 检查和 HTML 结构请求。真实协议检查在本地线程中运行库本身，不依赖伪造语言响应，也没有自动打开应用做视觉验收。

stash、rebase/cherry-pick 的继续/中止、未跟踪文件的可恢复清理、PR 与真实远程凭据验收仍未完成。子模块及目录/文件类型冲突仍交给原生终端处理，不冒充普通文本编辑。源码管理主流程并不代表这些能力已经实现。
