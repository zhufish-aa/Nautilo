# Nautilo 下一迭代实施计划

更新日期：2026 年 11 月 16 日  
状态：O01—O08 与 N01 本轮源码已落地；构建及定向验证记录见 [本轮实施与交接](quality-iteration-2026-11-16.md)，真机与完整性能验收单独列示  
适用范围：Electron 桌面端、React 前端、Rust 后端、Android 客户端及现有 Harness 插件  
功能基线：[Nautilo 已实现功能总览](implemented-features.md)

本轮主线是优化已有功能的实际使用体验：聊天连续、同会话热启动更快、多项目易管理、手机恢复不扰人、Git 操作及时、团队活动可读、资源问题能就近解决。界面和动效与这些流程一起交付。

新增能力中，桌面草稿跨重启恢复属于本轮连续体验的必要补齐。正文搜索、手机产物获取、配置方案页面和独立工具服务保留详细设计，作为后续扩展交付，不排在现有体验优化之前。

已有的流式聊天、团队 DAG、手机 Diff、P2P、MCP 复用、原生配置导入、上下文和请求日志继续沿用。它们的已修复问题列入回归场景，不重新包装成新增功能。

### 本次实施记录（2026-11-16）

- **会话定位栏：** 桌面左侧按实际提问顺序显示刻度；支持悬停预览提问 / 回复摘要、点击跳转、按会话保存书签和键盘定位。跳转直接接入已有虚拟列表，不要求目标消息先出现在 DOM 中，也不改变消息顺序。
- **O01 阅读连续性：** 切换会话保留本次应用运行中的阅读位置及跟随状态；返回旧会话不当作新发送而强制跳到底部。委派 / 提示过滤改为集合查找，减少长轮次的重复扫描。
- **N01 草稿恢复：** Rust 与 Node daemon 增加独立草稿 Repository、加密存储和版本比较写入；文本和附件引用不进入 localStorage 或审计日志。启动恢复保留新输入，已接收的消息身份参与对账，未知结果不自动重发。正常关闭等待保存回执；冲突或保存失败保留本窗口内容并提供明确处理入口。
- **O04 手机同步：** 文本、思考和工具输出继续增量投影；普通运行活动和文件事件不再拉取整份历史。结束、审批、提问和显式历史同步保留必要核对。连续流式更新合并到逐帧滚动，手动查看历史时停止跟随。
- **O03 首项调整：** 发送前的工作区基线扫描转入阻塞线程，保留扫描完成后再启动原生运行的顺序，不阻塞异步 IPC 工作线程。此项不能等同于已经减少 CLI 初始化时间；常驻复用和 MCP 命中仍需按原计划测量。

已完成的定向验证：桌面类型检查；会话排序、定位、草稿版本和退出握手的 45 项测试；Node 草稿服务 5 项测试；Rust 草稿 / 加密 4 项测试；Android Kotlin 编译与 4 项同步策略测试。另用真实 React 时间线及虚拟列表、合成 DOM 几何验证了 600 行长会话的屏幕外跳转、二次对齐、预览、书签、键盘和返回位置；这不替代用户设备上的视觉及网络验收。

以上为最初阶段记录。随后已接入长单轮逐事件虚拟化、项目导航位置、文件预览身份与模型缓存、单任务重试、资源同步冲突与请求关联诊断，详见本轮实施记录。仍需用户设备验收手机后台 / 网络切换和完整 P50/P95；协议 fixture 的复用结果不等于各家真实模型端到端性能。

**范围更正：** 按用户最新要求，已移除项目名下面的“全部 / 运行中 / 待处理”筛选行及其筛选状态。侧栏保留项目折叠和直接会话列表；状态集中在运行驾驶舱查看，不再把这一排入口加入项目侧栏。

### 1.2 现有功能具体怎样优化

以下场景是本轮优化目标。历史上已经修复的问题作为保护项；尚未重现的卡顿先定位，不能为了“完成优化”重复重写正确逻辑。

#### O01 聊天和发送的连续体验

**用户结果：** 发消息、看流式、引导、切会话再回来，内容和位置连续；退出重开也能接着输入。

- 保留现有乐观显示与稳定消息身份。把流式更新限制到实际变化的消息 / 活动，避免一次 token 更新带动整个工作区重算。
- 当前时间线已有按行虚拟化，但一行可能包含整轮的大量活动；对数百条工具事件的单轮单独控制渲染量，不能只按会话轮数判断是否需要虚拟化。
- 固定消息更新、滚动跟随和展开收起的先后关系。用户看历史时不拉到底部；折叠、展开或历史补读后保持正在阅读的内容锚点。
- 沿用已有顺序与消息身份规则：用户引导插在真实接受位置，后续回复跟在它下面；不能按整轮结束时间把整轮内容一次搬动。
- 输入框、模型选择与队列共享明确的提交状态，保留正在输入的下一句；增加 N01 的持久化恢复。
- 调整发送动效的衔接，避免“消息已显示 → 收到回执 → 整条重播 / 位置跳动”。历史读取不播放新消息入场。
- **验收：** 一个包含 500 条活动的长轮次持续输出时仍能输入、展开、查看历史和引导；切走回来保持阅读位置，最终正文不跳位、不重复。

#### O02 多项目会话管理

**用户结果：** 管理多个工作目录时，始终知道当前在哪、哪些任务需要处理，返回旧工作只需少量操作。

- 在现有项目分组上明确当前项目，保存每个项目的展开、滚动和最近查看位置；回到项目恢复原来的上下文。
- 侧栏直接展示项目和会话，不在各项目下面插入筛选栏。全局驾驶舱继续提供状态筛选及跨项目汇总，同一批会话不在右侧重复展示。
- 标题、所属项目、状态和时间按主次排列；过长标题有完整查看入口，状态不靠文字颜色单独表达。
- 驾驶舱待处理项直接指向审批 / 提问位置；运行卡片显示实际最近活动，完成未读项支持直接查看结果。
- N02 正文搜索作为可独立交付的增强，未完成搜索索引也不阻塞现有会话导航精修。
- **验收：** 使用 10 个项目、200 个会话和混合运行状态，能快速找出待处理任务并回到原会话；选择会话不改变历史排序。

#### O03 Harness 和 MCP 的启动开销

**用户结果：** 同一会话再问一句，复用能复用的环境；确实等待时能看懂等待发生在哪。

- 使用已有请求日志拆开配置读取、插件绑定、原生握手、MCP 和首个模型事件，分别检查冷启动与再次发送。
- 对热路径审计重复的版本检测、配置扫描、模型 / 模式发现和资源同步：输入与版本未变时复用对应结果，显式刷新或真实变更时失效。
- 对常驻进程增加可追溯的复用 / 重建原因。只有协议要求、配置身份变化或进程失效才重建，不把结束一轮当成退出会话。
- 校对 MCP 池的实际命中和租约释放；配置、目录、认证不同必须隔离，同一配置不得被重复拉起而无说明。
- 不全量预启动所有账号和 Harness。围绕正在使用的会话预热，空闲回收前检查子 Agent、交互与后台任务。
- **验收：** 同配置连续三轮能在请求日志确认复用；切换连接时正确重建；旧原生任务不会因回收被杀。收益报告区分宿主开销和模型 / 网络时间。

#### O04 手机前后台与连接反馈

**用户结果：** 切后台回来像回到原来的聊天，不是重新进入一页空白、不断弹错或反复确认有没有发送成功。

- 保留现有前台服务、游标补读和待发送对账，梳理页面重入产生的重复读取与旧请求回写，不再重复启动多个同步循环。
- 分开显示传输连接、历史同步和实际任务状态。同步暂缓不将正在运行的任务改成失败，也不把只读超时报成“消息未发送”。
- 短暂恢复期间保持消息、输入和当前位置；持续失败再就近提供重试。恢复成功只清理本次连接提示，不清掉业务错误。
- 同步恢复分批合入投影，保持滚动锚点，减少每批事件触发整页重组；用户立即输入和停止不等待全部历史补齐。
- 配置弹层固定操作区，模型列表独立滚动，键盘关闭与发送按钮变化连贯。已有上下文、团队入口保留。
- **验收：** 切后台 30 秒 / 5 分钟、换 Wi-Fi / 蜂窝和短时断网后恢复；不丢已接收内容、不重复发送、不刷出一串瞬时红条。系统强制停止单独记录，不伪装成应用可以永久保活。

#### O05 文件和 Git 的操作手感

**用户结果：** 连续选文件、读 Diff、编辑和提交都有即时反馈，文件再多也不用等整个仓库重新加载。

- 在已有缓存上区分仓库状态、文件内容和视图偏好；切一个文件不重新构造整个面板和全部编辑器。
- 旧预览在新内容加载时保留明确的文件身份与加载状态；新文件就绪后整体切换，不能把 A 的代码暂时冠上 B 的文件名。
- 自动状态刷新合并已有请求，编辑时不抢焦点；实际变更后精确失效。保留前台自动刷新，不改为只靠用户点刷新。
- 暂存操作局部反馈并按工作树顺序执行；旧状态、失败或部分成功明确呈现。提交、保存和刷新各有自己的忙碌状态。
- 默认折叠无关工具操作，保留文件类型图标、行号、完整文件、真实差异、统计与可调尺寸。未知基线和二进制不装作普通代码 Diff。
- **验收：** 在 500 个变更文件中快速选择不同文件，旧请求不覆盖新选择；编辑、暂存、提交和外部修改后仍显示真实版本，未保存草稿完整保留。

#### O06 团队任务与工具活动的可读性

**用户结果：** 看一眼知道谁在做什么、为什么在等、得到什么结果；技术原始数据可以展开，但不淹没工作内容。

- 使用已有任务 DAG 和父子关系，不改成虚构的线性步骤。默认突出正在运行的分支、阻塞原因和需要用户处理的节点。
- 委派卡片统一展示成员、目标、当前实际活动、状态和结果入口；并行卡片同时更新，不通过卡片上下位置暗示串行。
- 对同一委派只保留一个主要入口。已被卡片承载的内部记录不再以原始任务 ID、英文派发文本重复进入普通正文。
- PTC 父调用显示本段目的和子工具数量，展开后能逐项看命令 / 读写文件 / MCP 及后台状态；不把所有事情摘要成“运行代码”。
- 失败卡片提供实际原因和相应会话入口；恢复只针对选定任务范围，不重跑已成功产生外部副作用的分支。
- **验收：** 两个并行成员加一个依赖任务，能区分运行、等待和失败；主轮结束后子任务仍可更新，手机和桌面看到相同任务身份。

#### O07 连接和资源管理的操作闭环

**用户结果：** 选了哪个连接、工具来自哪里、哪里失效、怎样修复，都能在对应位置看明白。

- 沿用已有诊断和会话工具清单，把当前连接版本、原生账号、传入资源、原生注册结果和实际调用关联到同一次请求。
- 模型 / 账号切换先保留可用缓存，明确变化对象；普通选择不触发重复全量扫描，手动刷新才重新发现可刷新资源。
- MCP / Skills 按来源与目标归组，显示是否由 Nautilo 管理、原生位置及外部修改状态；同名不同来源可区分。
- 同步预览直接展示有变化和冲突的条目，空变化不打断；应用和撤销后能回看实际结果，缺凭据不误报端点不兼容。
- 失败位置就近提供登录、诊断、查看日志或配置入口。请求耗时仍只在请求日志中，不向聊天再塞一套诊断卡。
- **验收：** 复现一个缺工具和一个过期授权，能从当前会话定位到对应连接 / 来源并修复，不能通过换另一个账号假装原账号好了。

#### O08 页面质感与有呼吸感的动效

**用户结果：** 页面有清楚层次、文字扎实、操作有反馈，切换与展开连贯；不是把边框全部删掉或全页堆卡片。

- 先统一文字、图标基线、控件高度、留白和背景层级，再落实到高频页面；保留原 Logo、已确认布局和浅深主题。
- 黑白主色配合局部状态色。主要文字清晰，辅助文字仍可读；代码独立使用等宽字体和与主题匹配的高亮。
- 页面切换保留已有内容到新页面可显示，不让空白帧充当转场；面板开合、返回与来源位置对应。
- 发送、按压、选中、展开使用可打断的弹性过渡；实际运行标记有轻微呼吸。流式 token 不触发整块动画，结束后停止循环动效。
- 每个页面同时处理空、加载、部分内容、失败和长内容，而不是只做好一张有数据的截图。
- **验收：** 侧栏、会话、模型选择、团队、Git、资源和手机输入 / 弹层逐页对照；连续快速操作不排队播放过时动画，低性能设备仍可立即点击。

### 1.3 范围边界

不新增 Harness、iOS 客户端、云托管或新的壳层；DeepSeek 原生 Web 交接继续排除。完整 PR 工作流、stash、rebase / cherry-pick 工作台进入后续候选，不混入现有 Git 主流程的精修。

保留用户当前账号、配置优先级、会话身份和原生功能。手机仍按已配对的本人设备操作全部项目，不新增逐项目权限分配。直连模式不自动改成中继，浏览器仍只有用户点击接管才交还控制。

## 2. N01 桌面草稿跨重启恢复

### 当前差距

[composer-drafts.ts](../apps/desktop/src/renderer/src/stores/composer-drafts.ts) 原有草稿、待提交、失败重试和版本保护仅在内存中；本次已接入 [composer-persistence.ts](../apps/desktop/src/renderer/src/lib/composer-persistence.ts) 和后端加密草稿存储。异常退出仅能恢复最后成功落盘的版本，真实桌面退出 / 升级验收仍应单独记录。

Android 的加密草稿和源码编辑器的持久化草稿已存在，本项只补桌面聊天输入的缺口，不重新实现那两套机制。

### 实施内容

1. 后端增加草稿存储，区分新会话草稿、已有会话草稿和待确认提交。按项目 / 会话隔离，保留编辑版本与提交身份。
2. 文本和附件引用加密保存；渲染层只调用白名单接口，不把提示词及电脑路径直接写到 localStorage。
3. 输入先在本地响应，后台合并短时间内的保存；失焦、切换和正常退出触发落盘。异常退出只承诺恢复最后已保存版本。
4. 启动时恢复草稿，保留正在输入的新版本；迟到的旧保存或发送回执不能清掉新编辑。
5. 对“电脑已接受但界面未收到回执”的提交先查已有消息 / 请求身份。不能判断结果时显示待确认，不自动重新发一轮。
6. 附件恢复后校验是否仍可读取。失效项提供移除和重新选择；新会话草稿在创建成功后迁移到真实会话。

### 用户流程与验收

- 在两个项目分别输入文字和附件，重启后各自恢复，互不串入。
- 发送期间继续编辑下一句，上一句成功回执不清空下一句。
- 模拟接受回执丢失，重开后只出现一次用户消息和一次实际运行。
- 磁盘不可写时保留当前编辑，给出简短、持续可见的保存失败状态，不伪报已保存。
- 删除会话 / 项目后清理对应草稿；用户主动丢弃后不再恢复。

涉及模块：桌面 composer store、新的后端草稿服务 / Repository、凭据存储、会话接受回执及 IPC。

## 3. 扩展 N02 从搜索结果直接回到原消息

### 当前差距

[sidebar-navigation.ts](../apps/desktop/src/renderer/src/lib/sidebar-navigation.ts) 目前匹配标题和项目名称。用户记得“之前讨论过缓存迁移”，但会话标题不是这几个字时，仍很难找到那次工作。

### 实施内容

- 在现有搜索入口中增加“消息”结果，保留标题搜索的速度。可按项目、Harness 和时间范围缩小结果。
- 结果显示会话名、项目、消息时间与命中片段；区分用户消息和回复，不直接展开整段正文。
- 点击后进入对应会话，按稳定消息身份加载前后文、滚到原位置并短暂突出命中内容。长会话使用定点读取，避免为一个结果加载全部历史。
- 首版索引用户消息和助手正文。工具完整输出、私有推理、密钥和原生配置文件不进入默认搜索。
- 索引在后台增量更新；消息修改、删除和项目移除同步处理。索引可重建，不阻塞会话启动。
- 首版支持中文片段、英文、路径和符号的明确匹配；根据实际 SQLite 构建选择索引方式，不假设英文分词器自动支持中文任意子串。
- Android 接入同一受限搜索能力，结果来自已连接电脑，不额外复制整套历史到手机。

### 验收

1. 标题不含关键词但正文包含时可找到；中文、英文、文件路径均有固定样例。
2. 命中旧会话中的引导消息，跳转后顺序不变，不触发发送和模型调用。
3. 历史分页、重新连接、编辑和删除后，结果不跳错消息或显示已删除正文。
4. 搜索进行中改关键词，只显示最后一次查询的结果。
5. 结果分页有上限；索引重建时现有标题搜索仍可使用。

涉及模块：后端消息查询与索引、搜索 IPC、桌面搜索入口、时间线定位、Android 搜索及导航。

## 4. 扩展 N03 手机查看和保存电脑生成的产物

### 当前差距

手机已经能查看聊天附件图片和部分项目文件；[移动端说明](../apps/mobile/README.md) 仍明确指出生成产物主要展示名称与路径，缺少统一的远程产物下载流程。已有项目预览不能替代这个交付入口。

### 实施内容

1. 产物卡片提供真实名称、类型、大小、生成来源和可用状态。图片可点开，其他格式进入适合的预览或保存流程。
2. 通过产物 ID 获取描述与内容。电脑核对它与当前会话 / 项目的关联，不新增接受任意绝对路径的下载接口。
3. 复用远程分块传输机制，增加版本、偏移和校验信息。内容变化时停止续传并提示重新读取，避免拼接两个版本。
4. Android 使用系统文件保存和分享入口；大文件走有进度、可取消的传输任务，不长时间阻塞聊天。
5. 已支持的图片、SVG、PDF、文本 / 代码复用现有预览器。Office 首版提供保存与系统应用打开，不承诺手机内完整编辑。
6. 预览、下载缓存及临时文件有容量和清理入口；断开电脑、切换设备及主动取消时正确结束读取。
7. 删除、移动、权限拒绝及旧后台不支持等情况保留准确原因，不显示空白页，也不把失败传输标为完成。

### 验收

- 让 Agent 生成图片、SVG、PDF、文本及一个 Office 文件，从卡片完成预览或保存。
- 保存文件与电脑源文件校验一致，中文名和同名文件处理正常。
- 传输途中切后台 / 断网再回来，能继续或明确重试，不产生重复目标文件。
- 文件生成后被外部修改，续传不会混合内容；已删除产物不诱导无限重试。
- 下载期间聊天流式更新继续；点击取消只停止传输，不停止电脑 Agent。

涉及模块：产物 Repository 与读取服务、远程协议、Android 传输控制器、产物卡片、预览 / 系统保存。

## 5. 扩展 N04 配置方案从后台接口变成可使用流程

### 当前差距

[integration_service.rs](../rust/nautilo-core/src/application/integration_service.rs) 已有配置方案捕获、导入导出、预览和应用；当前没有完整桌面页面。本项补使用流程，不重新宣称开发配置存储和同步协议。

### 实施内容

- 设置提供配置方案入口，按名称保存当前选择的 Harness、连接和工具资源，也能从文件导入。
- 保存前选择包含哪些项目；此处“项目”指配置条目，不是把用户代码仓库打包进去。

- 应用前重新核对预览版本，显示逐项结果及失败原因；出现部分成功时保留已完成项，只对未完成部分重新生成计划。
- 复用现有资源同步的历史和撤销；连接与 Harness 配置的恢复按其实际版本实现，不把资源撤销误称为整份方案可撤销。
- 方案文件采用版本化格式，导出前显示敏感字段处理结果和不可迁移项。

### 验收

1. 现有电脑保存方案，干净数据目录导入后能定位缺少的依赖并补齐。
2. 原有原生 MCP / Skills 和用户配置不会因导入被整份覆盖。
3. 预览后发生外部配置修改，旧计划被拒绝，原始内容保持可恢复。
4. 任一条目失败，结果准确区分已应用和未应用。
5. 导出文件不包含 API 密钥、登录令牌和本机登录目录；文案不声称导入等于已登录。

涉及模块：设置页面、配置方案 UI、现有 integration service / resource service、依赖检查与 IPC。

## 6. 扩展 N05 图片视觉搜索服务接通真实执行

### 当前差距

当前 `toolServices` 已保存 image / vision / search 的连接、版本和模型绑定，但没有完整的统一工具消费流程。账号网关已实际工作，不能将两者混为一项“已完成路由”。

### 实施内容

- 在连接设置中配置三类工具的执行连接和模型，明确本次实际使用者；主聊天模型保持用户选择。
- 后端增加按用途分开的执行器，复用现有 API / 账号协议实现，统一请求身份、取消、用量和错误事件。
- 将执行器通过现有宿主工具桥提供给声明支持的 Harness，避免每个插件再写一套同名服务。
- 图片生成结果进入产物记录，视觉请求使用真实图片内容，搜索保留来源链接；不只回传“调用成功”。
- 官方账号能力仅按实际协议接入；供应商不支持时准确报能力缺失，不伪装成官方客户端，不擅自换账号 / 端点。

### 验收

- 主会话使用连接 A，工具使用绑定的 B；请求日志能够核对到两个真实身份。
- 三类工具分别有成功、取消、认证失败和不支持场景；图片有实际可读取产物，搜索有可追溯来源。
- 工具失败保留当前会话和主模型，不丢掉上一轮历史。
- 同一工具在至少一个内建 Harness 和一个插件 Harness 中通过相同宿主契约调用。
- 未验证的原生账号能力标明范围，不能只用模拟 API 结果宣布官方账号全量支持。

涉及模块：integration service、独立 tool service 执行模块、宿主 MCP / 动态工具桥、账号网关、产物与请求日志。

## 7. 高频页面与动效的共同标准

### 7.1 保留的设计基础

使用现有品牌、Noto Sans SC、JetBrains Mono、浅深主题和已确认布局。默认保持黑白层次，状态色承担状态提示；不为精修另加紫色品牌、不随功能修改替换 Logo。

目标是清晰的空间结构、清楚的文字、可预期的操作和有连续感的动态。边界用材质、留白、细描边和局部背景组合表达，不简化成所有区域全白，也不重新堆大灰框。

### 7.2 页面交付清单

本轮优先完成 O01—O08 涉及的页面。表内标为“后续扩展”的界面在对应功能实施时采用相同标准，不计入本轮阶段交付。

| 页面 | 实际改动 | 验收重点 |
| --- | --- | --- |
| 项目 / 会话侧栏 | 明确项目切换与列表层次，统一状态和选中反馈，保存列表滚动及折叠状态 | 多项目、长标题、大量历史仍易定位；点击会话不改变列表排序 |
| 会话及输入区 | 将持久草稿、待确认发送和恢复状态放进既有输入流程，统一附件与配置弹层 | 不额外增加常驻状态大卡；键盘、配置选择和发送连续衔接 |
| 搜索（后续扩展） | 标题与消息结果层次、命中片段、筛选、键盘和定位反馈 | 不把命中全文塞进列表；关闭搜索回到原位置 |
| 模型 / 连接选择 | 紧凑模型行、可见连接入口、长模型名、独立列表滚动和固定操作区 | 多模型不会撑高整个面板；账号 / API 不藏在不明显的折叠标题里 |
| 手机文件 / 产物（产物传输为后续扩展） | 真实文件类型、预览页、传输状态、系统保存 | 点文件进入详情；不在列表尾部追加大预览，不用一个图标表示所有类型 |
| Git 与文件审阅 | 文件身份、加载过渡、局部操作状态、编辑焦点、真实统计 | 连续选择不串内容；暂存和提交不靠整个面板重载反馈 |
| 连接与 MCP / Skills | 当前连接、来源分组、问题入口、同步差异与应用结果 | 同名资源可区分；工具是否可用能定位到实际来源 |
| 团队与驾驶舱 | 聚焦待处理原因、成员活动、并行关系和回到会话的路径 | 已有卡片不再重复展示内部委派文本；空状态不拉出大面积无意义留白 |
| 配置方案（后续扩展） | 方案列表、逐项差异、依赖补齐与应用结果 | 以对象和变化组织内容，避免一整页参数表单与重复说明 |
| 错误与恢复提示 | 区分业务失败、同步暂断和未确认发送，操作就近出现 | 不闪出瞬时红条；不把同一个错误重复放在正文和底部 |

### 7.3 动效交付

在现有动效上统一页面切换、展开、发送和返回的空间关系；每个过渡可被新操作立即打断。发送时输入内容到消息气泡有清晰衔接，发送按钮和等待反馈连续变化。

状态圆环、实际运行中的标记可轻微呼吸；等待用户、失败和已完成使用各自静态或状态反馈，不让整页持续漂浮。流式每个 token 不重播整块动画，历史载入不冒充新消息到达。

首次实现以现有曲线和时长为基准，优先使用 transform / opacity；输入区高度随键盘变化单独处理。关闭系统动画后保留同样信息和可用操作。

### 7.4 视觉验收

每个受影响页面提供浅色、深色、常见桌面宽度及手机键盘打开状态的对照。检查文字重量、状态可辨认性、图标基线、长内容、焦点和触控区域。

已有设计稿约束的页面按同尺寸对照；内容数量不同不通过写死占位数据凑图。用户不需要再逐个指出重复说明、文字过灰、按钮遮挡等共同问题。

## 8. 性能目标与计量

### 当前基础和目标

现有虚拟化、常驻、模式缓存、MCP 进程池和请求日志继续使用。本项只针对测量到的剩余开销修改，不再以“加入缓存”“支持常驻”作为成果。

| 观察点 | 本轮处理 |
| --- | --- |
| 已访问会话切换 | 检查重复请求、状态重置、已挂载内容重建和大范围订阅，保留必要刷新 |
| 再次发送 | 分开记录会话复用、配置变化导致重建、CLI 自身初始化和宿主开销 |
| MCP 首次与再次调用 | 检查实际池命中、工作目录 / 环境变化及失效回收，减少可避免的重复握手 |
| Git 文件切换 | 检查状态刷新与差异读取互相阻塞，旧预览保留到新内容就绪，不闪空白 |
| 手机流式 | 检查事件补读和页面重组，合并视图更新，保留事件顺序与用户滚动 |
| 新增搜索 / 传输 | 索引和文件读取在后台有界执行，不抢占聊天输入与取消通道 |

### 计量方式

在固定数据和同一设备上区分冷启动、热路径、配置改变后重建；本地界面耗时与模型 / 网络耗时分别报告。重建需要写出原因，不能把所有等待都归到“模型慢”。

建议验收目标如下，实施前先保存当前基线；这些是目标，不是当前实测数值：

- 发送、展开、切换等本地操作的可见反馈 P95 不高于 100 ms。
- 已访问会话的缓存内容切换 P95 不高于 150 ms；远程拉取时间单独计算。
- 新增实现不引入持续超过 50 ms 的前端主线程阻塞；大文件计算、索引和传输分块移出交互线程。
- 热路径只有确实需要重建时才重新启动原生环境；配置未变仍重建的情况逐条说明。
- 流式同步没有新增的周期性整页重挂载和持续积压；后台任务、审批与取消仍能及时到达。

报告给出场景、数据量、设备、次数、P50 / P95 和前后结果。模型响应速度不设脱离供应商与网络条件的绝对保证。

## 9. 原生能力与跨端回归

以下是既有能力的保护项，不计为新增功能。按本轮改动选取对应组合验证，复用已有夹具和证据，不在每次样式调整后重复跑所有 Harness。

| 场景 | 验收要求 |
| --- | --- |
| 连续对话与引导 | 保留原生会话；引导后的回复在引导下面；事件和最终正文不重复 |
| 原生资源 | 当前账号的 Apps、MCP、Skills、插件与原生配置优先级保持原样 |
| 提问与审批 | 可回应、可取消、原位更新，不能把未知请求统一自动取消 |
| 工具与子 Agent | 真实调用 ID、并行更新、父子归属及背景活动正确 |
| 用量与压缩 | context / turn / session 不重复累计，未知不显示为零 |
| 手机离开与回来 | 电脑任务继续；读同步恢复，未确认发送先对账 |
| 文件与 Git | 正确前后版本、真实统计、非 Git 目录、冲突保存及旧版本拒绝 |
| 浏览器 | 空间独立标签、仅显式接管、全关停止旧操作而新调用可重新打开 |
| 取消与退出 | 中止真实请求并保存尾部状态，不取消其他会话或丢弃后台活动 |

固定记录 Harness / CLI / 插件 / PC / APK 版本、账号类型、协议和验证范围。离线夹具、真实 CLI 握手、真实模型工具调用、用户真机验收分别标记。

发现原生协议未暴露的能力，记录具体限制并保留已有可用入口；不通过关闭功能或切换账号让检查变绿。遇到接入遗漏则在对应 adapter / 插件修复，不能只改错误文案。

每阶段围绕用户能感受到的变化交付，不以“加完接口”或“改完样式”收尾。开始实施第一阶段后，不穿插新增 Harness、配置平台或其他大功能。扩展项未开始时保持待实施状态。

## 11. 代码组织与数据兼容

- 草稿、搜索、产物传输、工具服务各有独立服务与 Repository；协议字段集中在 schemas / domain，迁移集中管理。
- Rust 承担执行和持久化；涉及共享 IPC 的变更同步 Node 对照实现。Renderer 不接触 shell、SQLite 或任意本地路径。
- Android 新增搜索 / 产物控制器，不继续把所有网络和页面逻辑堆进 MobileViewModel。
- 组件按业务状态接收数据，通用主题与动效留在共享层；不靠同一组件内逐 Harness 名称判断全部行为。
- 新协议声明具体能力，手机连接旧 PC 时隐藏不支持的操作并保留现有聊天，不用一次“资源不存在”替代兼容处理。
- 后端新数据库迁移验证旧数据升级；新版本产生的索引和缓存可重建，不能把历史会话当临时数据清理。
- 构建缓存、临时目录、测试数据和安装包继续放 D 盘；用户源码、账号、会话和活跃 worktree 不参与缓存清理。

## 12. 最终验收任务

以下任务从已有真实使用方式出发，检查增量是否让完整流程更顺畅：

1. **退出后接着写**：两个项目分别输入内容和附件，退出 / 重开，继续发送；无串草稿、无重复提交。
2. **长单轮仍能操作**：持续输出数百条工具活动，期间输入、展开、看历史、发引导和切回会话，仍保持响应和阅读位置。
3. **再次发送更少等待**：同一配置连续对话，用请求日志核对复用和重建原因，报告宿主开销前后差异。
4. **手机回来直接继续**：切后台、短时断网及换网后恢复，不重复消息、闪空白或连续弹出暂断提示；原任务持续执行。
5. **多项目处理中断**：从驾驶舱找到待处理请求，跳到正确位置完成审批，再回到原项目和原滚动位置。
6. **连续审阅和提交**：大更改列表中快速选择文件，编辑、暂存和提交，不串代码、不抢焦点、不丢草稿。
7. **团队状态一眼可读**：并行成员、依赖等待、失败和结果有清楚归属，不重复显示内部派发记录。
8. **原地修复连接问题**：从缺工具 / 授权错误定位实际账号和资源，完成对应修复，保留原会话和其他原生能力。
9. **视觉与升级**：对照常用页面浅深主题、手机键盘和连续操作动效；安装新版本后沿用原配对、账号和历史。

验收结果使用“通过 / 部分完成 / 受限 / 未完成”，附问题和对应版本。没有完成的流程留在差异清单里，不靠改名、隐藏入口或增加说明文字宣布完成。
