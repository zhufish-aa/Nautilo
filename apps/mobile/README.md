# Nautilo Mobile

原生 Android 客户端：Kotlin、Jetpack Compose、Android Keystore，以及与桌面 Rust 后端相同的 Iroh 1.4.1 加密 P2P 协议。界面包含项目列表、新建会话、聊天、工作区、独立文件 Diff 和电脑连接页面。

## 使用

图片在选择后直接显示缩略图，发送后的消息也保留图片，可点开并双指缩放。会话历史同步附件的类型、名称和引用；`attachment.read` 只读取当前会话消息实际引用的附件，不接受电脑路径。手机缓存图片（最多 96 MiB，可清理）；重新打开会话或缓存被清理后会按需从电脑读取，单张图片上限 20 MiB。PC 需更新到支持手机附件目录的版本；旧图片不需要重传。

1. 安装 APK（Android 8.0 或更新版本）。
2. 在电脑 Nautilo 的「设置 → 远程连接」启用连接，点击「配对新设备」。
3. 手机选择「连接我的电脑 → 扫描二维码」，或粘贴配对链接。
4. 核对两端的六位数字，在电脑上确认。配对后即可操作全部项目，后来新建的项目也自动出现。

手机首页的「+」打开新会话首页：顶部切换或新建项目，底部直接输入第一条消息，发送时创建会话。默认输入区只有附件、占位文案和语音 / 发送按钮；聚焦后输入区展开为上下两行，文字在上，附件及设置图标在下。调节图标打开模型、推理强度及连接设置，盾牌图标打开权限和 Harness 原生运行模式。选项来自当前 Provider / 插件，未声明的能力不编造。模型和推理强度先本地选择，点「完成」统一保存；收起键盘或点聊天区域后恢复单行。

输入框旁「+」通过系统文件选择器添加附件。每条消息最多 10 个文件、每个文件最多 20 MB，可移除或单独发送。附件先复制到手机应用私有目录，再通过已配对的加密连接分块续传到电脑，发送成功后清理手机缓存；草稿和待发送记录保留附件信息。电脑将文件按现有消息附件机制交给 Harness。运行中的引导 / 排队仍支持文字，附件在当前轮结束后发送。

消息立即进入会话，正文、思考和工具事件持续同步。回复结构与 PC 版一致：顶部显示运行结果和用时，下面直接展示正文。供应商在输出前拒绝请求时，失败原因也显示在对应轮次，重新打开会话或发送下一条后仍可查看。聊天标题下不重复显示电脑连接状态。支持审批和问题回应、运行中引导 / 排队、主动停止、切换模型与推理强度、查看文件变更和团队成员。语音识别使用设备服务，聆听、错误和确认界面由应用绘制，不打开系统识别弹窗；麦克风和相机授权仍由 Android 系统管理。

同一轮的中间说明、工具调用和思考归入可折叠的执行过程，最终回复保留在折叠区外。Markdown 使用 CommonMark 解析，正文采用与 PC 相同的 Noto Sans SC（17sp / 28sp 行距），标题使用 600 字重；表格放大至 15sp，宽表独立横向滚动；代码块同样使用 Noto Sans SC，支持语法高亮和复制按钮。字体和许可证随 APK 提供，离线也能保持一致。模型面板只滚动模型列表，推理强度固定显示。

工作区点击文件进入独立 Diff 页面，提供真实新旧行号、增删底色、语法高亮、改动定位、换行和当前文件视图。差异和高亮在后台计算；没有原始快照时不把整个文件伪算成新增，未提供的内容明确显示不可用。

已有会话聚焦后点击调节图标，点击当前连接可切换账号或 API，选择对应模型后应用。运行中的请求结束后才能更改连接；有历史的连接切换会说明原生上下文影响，文字记录保留。Harness 原生运行模式在首条用户消息后锁定，与 PC 相同。手机不复制账号凭据，仍由电脑保存和使用；Codex、Claude Code、OpenCode 和反重力账号的跨 Harness 转发使用电脑端的同一个账号网关。

手机新建会话（含从旧会话新建）会为用户选定的跨 Harness 登录账号启用与 PC 相同的账号转发，然后再发送首条消息；保留会话绑定的账号及版本。Harness / 配置错误保留电脑返回的错误代码与原因，不再误报连接断开；单次响应超时仍保留待发送消息，也不会直接把现有连接标为离线。

项目列表的加号创建项目；项目卡片的加号在该项目内新建会话，文件按钮浏览该电脑上的项目目录。聊天 Markdown 链接、表格链接和行内文件路径可打开应用内预览，支持代码高亮、行号定位、文本 / Markdown、静态图片缩放、SVG 和 PDF 分页。大文本分块续读，超长行按显示段展开且保留原始行号；同名文件存在多个匹配时由用户选择。其他二进制 / Office 格式当前不提供手机内嵌渲染。

文件读取复用电脑端的项目边界校验，接受 Windows `D:/...` 和聊天产生的 `/D:/...` 形式，拒绝工作区外路径。每次手机 RPC 最多传输 512 KB 原始文件数据，完整文件最多 20 MB；跨块核对同一文件版本。切换电脑或退出预览会取消请求并释放预览内容，PDF 临时文件在关闭时清理。需要电脑端支持 `project.files` 和 `file.preview`。

新会话与聊天页采用干净的浅色背景、白色柔和圆角输入容器、低对比描边与深色发送按钮。模型和推理强度不常驻，配置入口只在编辑时显示。键盘、选择面板、页面切换及新消息衔接使用 Compose 动效，遵循系统动画时长设置；历史同步和回执更新不会重复播放入场动画。

电脑需保持开机、在线且 Nautilo 后端运行。自动连接优先尝试直连，必要时使用 Iroh 加密中继，无需给电脑开放公网端口。切到其他应用时不会主动断开电脑连接；后台消息连接服务使用低打扰通知维持连接，并可通过通知的「断开」停止。连接服务每 20 秒在原通道发出只读探测，不依赖聊天页面或用户发送消息；首次失败刷新路径，连续两次失败才回收旧通道并重新连接，避免短暂切网引起状态抖动。回到前台或默认网络变化时立即唤醒健康检查；不会重发聊天指令。有效连接续期有时限的 CPU 唤醒租约，断开及服务销毁时释放，离线后不无限持有；不保持屏幕常亮。返回时复用连接和消息游标，项目列表限量并发加载；草稿和待发送消息保留。Android 深度休眠仍可能限制网络并忽略唤醒锁；需要长时间后台直连时，可在系统应用电池设置中允许 Nautilo 不受限制地运行。系统强制停止应用或回收进程后仍可能需要重连。关闭手机页面不会停止电脑上已经接受的任务。停止任务需要主动点击「停止」。

「仅直连 · 跨网络 NAT 打洞」支持手机与电脑在不同网络间尝试建立 P2P。地址发现、端口映射和 QUIC NAT 控制帧继续工作；聊天、RPC、附件所用的 STREAM 载荷在 QUIC 发包、重传和收包层限制到 IP 路径，直连丢失时不改走中继。应用 DATAGRAM 只承载固定、限长的连接策略握手，不接受工作区 RPC。打洞超时会显示失败，不会自动降级。成功率仍取决于双方 NAT、UDP 和防火墙，不保证所有网络可打通。

「自动」允许直连失败后中继回退；「中继 · 公共或自定义节点」跳过 IP 直连，留空使用公共节点，也可填写兼容的自托管 Iroh 中继；「局域网离线」关闭互联网发现和中继，是单独的离线选项。旧版本名为「仅直连」的 `local` 配置会迁移到跨网 `direct` 模式。网络模式选择会立即应用；填写自定义节点后仍需保存。空白行和重复地址会被清理，未使用的自定义地址不阻止切换到自动或局域网。桌面中继状态只表示辅助通道可用，设备卡片区分「打洞中」与「P2P 直连」。

手机通过 v2 ALPN 和认证后的策略 DATAGRAM 确认电脑的模式，等待选中 IP 路径后才打开业务流。新版手机需配套新版桌面；自动模式桌面保留 v1 协议兼容旧手机，但仅直连模式要求新版手机。电脑返回当前地址，手机在认证后刷新缓存；`session.snapshot` 合并会话配置、运行及待处理交互，减少中继场景的往返次数。

本地 IPC `remote.diagnostics` 可读取当前及最近 8 次连接的路径、NAT 候选地址、打洞探测计数和 STREAM 帧计数；不会通过手机 RPC 或中继策略握手发送这些记录。候选地址不代表已连通，只有选中 IP 路径才表示直连成功。排查时应分别检查地址发现、候选交换和探测响应，不能只凭一轮 UDP 探测超时断言防火墙阻挡。公网地址缓存保留仍存活的 QAD 连接的首次观测，连接关闭或网络重置时重新发现。

桌面默认连接辅助服务遵循显式 HTTP(S) 代理环境变量；未配置环境变量时，Windows 可读取当前用户已启用的静态 HTTPS 代理设置，指定官方公共节点时同样适用。系统代理排除默认服务时不自动套用，PAC 和非官方自定义节点不套用这项静态系统代理回退。诊断的 `httpProxySource` 只返回来源，不泄露代理凭据。该代理只作用于 HTTP(S) 服务；在仅直连模式下不会改变 UDP 直连和业务 STREAM 的路径限制，中继模式则按用户选择允许中继传输业务数据。

桌面和手机使用同一份会话内容。Rust 将消息、思考、工具和交互请求按到达顺序写入 SQLite。重新打开按块的序号读取，打开期间只接收新增块、文本增量和状态更新。用户追加的消息和中间正文按原来的位置随过程折叠，初始提问、最终回复和交互卡保留。工具标签、输出和文件差异仍与桌面使用同一套显示规则。

聊天配置在同一窗口切换设置与选项，取消恢复进入前的选择。新旧会话、Harness 选择和权限模式共享按实际窗口约束测量的弹层，底部操作固定，中间内容可滚动；键盘和导航栏占位只计算一次。输入框聚焦时向上舒展，文字留白和工具栏同步过渡，失焦时收回，途中可立即反向切换；输入框持续挂载，焦点独立于异步键盘回调。按钮提供轻微按压回弹，选中勾选、配置页和新到达的执行内容使用短动效，流式文字更新和历史载入不重复入场。弹层全宽、不透明，禁用设备自带窗口动画，从底部展开，不做横向侧滑；关闭系统动画后立即应用最终布局。

会话右上角的圆环显示上下文占用，点击查看当前占用、上限、剩余空间和累计消耗。使用与 PC 一致的有效用量快照、缓存口径及当前模型上限回退；没有数据时显示未知，压缩后允许占用下降。支持原生压缩的 Harness 可直接在面板执行电脑端同一条压缩命令，运行中不可重复提交。新版电脑在历史同步中另外提供整个会话的用量快照，不受最近 200 条过程事件限制。

切后台时取消页面的历史与事件等待，连接服务及电脑任务继续；回到前台立即恢复读取，并沿用事件游标去重。流式事件最多每 250 ms 发起一次补读，按原始游标读取整批事件，避免逐块轮询耗尽电脑的请求预算。读取短暂中断先自动重试，不清空已有消息；连续 4 秒未恢复才显示提示，恢复后清除。授权失效与业务错误立即报告，后台心跳不会清掉操作失败提示。读取超时与发送结果未确认使用不同错误类型，同步超时不会声称有待发送消息；发送结果未确认时保留原指令 ID，按电脑回执核对，不重复生成新消息。

思考折叠行持续显示最新一行；超过一行时跟随文字末尾，不固定在开头或上一段。运行结束后保留末条摘要，重新折叠仍显示最新内容；展开的思考全文保持完整。

「模型与设置 → 协作团队」选择电脑端已配置的团队，或切回独立工作。新会话发送首条消息时直接使用同一个会话启动团队调度，保留已选账号、模型和原生会话身份。已有会话可在空闲时切换团队；运行中的团队及成员子会话不允许重新分配。

有团队的会话右上角可打开「团队任务」：按实际任务依赖显示串行步骤、并行分支和汇合，完成数量只统计成功任务。任务卡片显示真实成员、工具活动和已变更文件数，点击打开对应成员会话；依赖异常不会伪造执行顺序。成员页展示配置的成员及当前状态，底部返回会话和停止整个团队的按钮固定可见。页面在前台持续刷新，后台暂停页面读取，重新进入后恢复；需要同版本电脑端支持 `session.team` 和 `session.team.cancel`。

## 构建安装包

需要 JDK 21、Android SDK platform 35 / build-tools 35.0.0、NDK r28+，以及 Rust 的 `aarch64-linux-android`、`armv7-linux-androideabi`、`x86_64-linux-android` 三个目标。Gradle Wrapper 固定为 8.14.4，校验官方发行文件 SHA-256。`ANDROID_NDK_HOME` 可指定 NDK 路径。

`prepareNativeTransport` 调用 `scripts/build-mobile-transport.mjs` 构建三个 ABI。桥接源码在 `native/iroh-kmp`；上游依赖由 `scripts/prepare-rust-sources.mjs` 按固定版本下载、校验 SHA-256 并应用 `rust/patches`，生成到不入库的 `rust/vendor/generated`，保留上游许可证。原 SDK AAR 校验 SHA-256，仅复用其未改动的 Kotlin 类和资源，替换全部原生库。编译产物、缓存和校验记录在 `NAUTILO_ANDROID_BUILD_DIR/transport`。缓存命中前验证源码指纹与 AAR 校验值，缺少策略符号或任一 ABI 会终止构建。

在仓库根目录运行：

```powershell
$env:JAVA_HOME = 'D:/NautiloEnv/mobile/jdk/jdk-21.0.13+9'
$env:ANDROID_HOME = 'D:/NautiloEnv/mobile/sdk'
pnpm mobile:apk
```

Windows 上有 D 盘时，脚本默认把缓存、临时文件、构建输出和签名文件放在 `D:/CodexBuildCache/Nautilo/mobile`，复用已有的 `D:/GradleHome`。可以通过 `NAUTILO_MOBILE_CACHE`、`GRADLE_USER_HOME`、`NAUTILO_ANDROID_BUILD_DIR` 覆盖。

输出：`<缓存目录>/artifacts/Nautilo-Mobile-<版本>.apk`，附 SHA-256 文件。APK 包含 arm64-v8a、armeabi-v7a、x86_64。仅验证时可用 `-PnautiloScanTest=true :app:assembleDebug` 构建独立包名的「Nautilo 验证版」，与正式版并存。使用相同签名覆盖旧验证版时保留配对数据。

`node scripts/generate-desktop-presentation-fixtures.mjs` 直接执行 PC 展示函数，更新手机单元测试的对照数据。`-PnautiloWindowTests=true :app:testDebugUnitTest` 使用 Robolectric 检查完整 Android 弹窗、实际窗口边界、键盘占位和点击；`-PnautiloScreenshots=true :app:testDebugUnitTest --tests '*MobileDesignSnapshotTest*'` 渲染原生控件和 Markdown。窗口测试和截图测试分开运行，测试缓存同构建缓存放置于环境指定的目录。

首次构建会在缓存目录的 `signing` 子目录生成发布签名；此目录必须私下备份，后续更新沿用同一签名。**不要提交 keystore 或密码文件。** 也可以用 `NAUTILO_ANDROID_SIGNING` 指向自己的签名 properties 文件（`storeFile`、`storePassword`、`keyAlias`、`keyPassword`）。

## 结构

- `data/`：加密身份、配对电脑、草稿、待发送指令和增量会话投影。
- `transport/`：JNI Iroh endpoint、连接复用、独立双向请求流、身份校验。
- `MobileViewModel.kt`：生命周期、重连、历史与事件同步、会话操作。
- `ui/`：Compose 页面、应用自绘的控件 / 底部抽屉 / 弹窗、提问 / 审批、消息动效。
- `src/test/`：消息去重、累计增量、历史合并、配对数据校验。
- `src/androidTest/`：真实 Android endpoint 配对 / 重连，以及可选的真实 Harness 流式收发验证。

普通单元测试：

```sh
apps/mobile/gradlew -p apps/mobile :app:testDebugUnitTest
```

实际界面截图使用 Paparazzi 的 Android 渲染器，无需模拟器或真实账号：

```sh
apps/mobile/gradlew -p apps/mobile -PnautiloScreenshots=true :app:testDebugUnitTest --tests app.nautilo.mobile.MobileDesignSnapshotTest
```

截图报告位于构建目录的 `app/reports/paparazzi/debug/`。该流程直接渲染应用页面、原生 Markdown 和输入栏，等待页面动画结束后截图。

`ConnectionTest` 需要 instrumentation 参数 `invitation` 和电脑侧确认。`ConversationTest` 是显式运行的联调测试，需要已配对设备、可丢弃的电脑目录 `projectRoot`、可用 `agentId` / `connectionId` / `model`，会创建测试项目和会话并实际请求模型。它只处理此测试目录的首次授权提示，不自动批准其他原生请求。

手机端配对身份、电脑地址、草稿及待发送记录使用 Android Keystore 的 AES-GCM 加密，原子写入应用私有且不参与备份的目录。电脑账号凭据留在电脑端；手机不需要录入 API 密钥。

提问卡片按创建时间及原始事件顺序显示在所属回复中，回答后原位更新为只读记录；折叠执行过程后仍可见。后续轮次、回答回执及重新加载历史不会把旧问题追加到聊天底部。待处理的 Harness 原生审批也沿用这一时间线入口。

运行中发送引导后，以这条用户消息作为新的显示边界：之前的内容留在原位，之后的回复和执行过程按发生顺序显示在引导下方。原生运行身份不变，状态和耗时显示在最新回复段；流式正文转为最终回执及后台同步历史时沿用首次显示的位置。
